# Product

## Register

product

## Platform

web

## Users

QA engineers running and reviewing real Robot Framework test suites; qa_leads and admins managing users, permissions, and audit logs; developers checking defects assigned to them. A distinct power-user flow, Vibe Testing, is used by QA/test engineers exploring AI-driven testing: goal-based agent runs, SOW/video-to-checkpoint extraction, and visual regression review. This is internal software used during focused work sessions, often for hours at a stretch, not casual browsing.

## Product Purpose

AEP (Automation Execution Platform) is an internal QA platform that combines real, deterministic Robot Framework test execution with an AI-driven testing suite — goal-based browser agents, requirements/video-to-checkpoint extraction, visual regression auditing, and an autonomous orchestrator — plus a SOW authoring/rewrite pipeline. It exists to replace manual busywork in test creation and execution with AI assistance while keeping humans in the loop for review and approval. Success looks like QA engineers trusting the platform's results enough to make it their system of record for both manual and AI-assisted testing.

## Positioning

The one platform where deterministic Robot Framework execution and AI-driven "Vibe Testing" share a single system of record — real test runs, real evidence, and AI assistance without leaving one tool.

## Brand Personality

Approachable and a little playful — carried by the kawaii spider mascot — layered onto genuinely serious internal tooling. Trustworthy and precise where it counts (test results, evidence, audit trails); warm and human in the moments that aren't safety-critical (loading states, empty states, onboarding). Not corporate-sterile, not toy-like.

## Anti-references

Not a generic enterprise-gray admin template. Not so cutesy or gamified that it undercuts trust in test results. Avoid the disconnect where the mascot is playful but the surrounding UI feels like a bare spreadsheet — the mascot and the interface should read as one brand, not a logo bolted onto default components.

## Design Principles

Real signal over decoration: animation and copy should never claim progress that isn't actually happening. Confidence where it's safety-critical, warmth everywhere else: evidence, results, and audit logs stay precise and sober; loading, empty, and onboarding states get the mascot's personality. One brand, not two: the playful mascot and the visual system should feel like the same product.

## Accessibility & Inclusion

WCAG AA baseline. `prefers-reduced-motion` support is required on all animation — this is software the same people use for hours at a stretch, not a one-time marketing impression.
